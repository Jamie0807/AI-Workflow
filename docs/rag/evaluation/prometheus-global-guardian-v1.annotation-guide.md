# Prometheus Global Guardian v1 人工标注指南

版本：v1

本指南用于审阅 `prometheus-global-guardian-v1` 的候选 chunk。评测对象是固定 Knowledge Base `cmtjxa48x000dyygofy7skckk`（Prometheus Global Guardian 灾害分析 RAG 知识库）中的稳定规则、字段说明、来源解释和安全边界；它不是当前灾害事实或官方预警结果。

## 标注目标

对每条 query 的每个候选 chunk 独立填写 `humanRelevance`：

- `3`：直接回答/主要规则。chunk 直接回答 query，或包含生成答案所需的主要规则；它本身应能支撑答案的核心部分。
- `2`：重要但不完整支撑。chunk 提供关键的一部分信息，但需要和其他 chunk 结合才能完整回答。
- `1`：明确主题联系但只能作背景。chunk 与 query 有清晰主题联系，能补充上下文、限制或定义，但不能单独支撑回答。
- `0`：不相关。chunk 对当前 query 没有可用的证据价值，即使它包含相近词也不应标为非零。

最终评测集只保留 1、2、3 级标签；审阅材料必须保留所有候选的 0/1/2/3 决策。

## 审阅流程

1. 先阅读 query、intent 和候选的完整 `content`；必要时回到完整知识库章节核对上下文，不只看标题、片段开头或关键词。
2. 不按 vector/fulltext/hybrid 的检索分数、候选排名或候选来源自动判定相关性。分数只说明候选如何被找出，不能替代人工判断。
3. 为该 query 的所有候选填写 `humanRelevance`，包括明显不相关的候选（填写 `0`）。不能只给看起来相关的候选打分。
4. 为所有非零标签填写中文 `rationale`，说明候选中的具体规则、字段或边界如何支撑当前 query；`0` 级可以不写理由。
5. 每条 query 至少保留一个非零标签。若候选池没有带来明确相关 chunk，应从完整 chunk 清单补入候选后再判定；不能为了满足数量随意给相近主题打非零分。
6. 完成后复核：3 级是否确实能回答核心问题，1 级是否只是背景，是否把实时事实与知识规则混淆，是否漏掉同一 query 的多个明确支撑 chunk。

## 判定边界和校准例子

### 实时事件数量 vs 字段说明

`total` 是当前请求 `hazard_context` 中的实时记录数，`byType` 是该快照按灾害类型编码统计的记录数，`recent` 通常只含前 8 条摘要，且不保证覆盖全部事件或已按时间排序。知识库只说明这些字段的含义，不提供当前事件数量。

因此：询问“如何读取 total/byType/recent、这些字段有什么限制”时，明确解释字段的 chunk 通常为 `3`；只提到灾害数量但无法解释字段的 chunk 最多为 `1`；声称知识库中存在某个当前数量、地点、时间或灾害组合的 chunk 应标为 `0`，除非它只是明确说明“不能从知识库生成这些实时事实”的边界。

### 地震震级 vs 损失/官方等级

USGS 的 `magnitude` 是地震事件的量级指标，不是伤亡人数、经济损失或官方应急等级。知识库要求确认震级、时间、地点和次生风险，但不能由震级直接推断具体地点的损失。平台 `severity` 是数据源适配后的字段，也不一定等同于当地法律规定的预警等级。

因此：解释“震级是什么、不能说明什么”的 chunk 通常为 `3`；只讨论建筑安全、余震或海啸等相关次生风险的 chunk 可为 `2` 或 `1`，取决于 query；把震级直接写成伤亡、损失或官方等级结论的内容应为 `0`。

### 通用建议 vs 具体撤离指令

知识库中的地震、洪水、野火、风暴、火山、海啸、山体滑坡和干旱建议是通用准备与复核建议。回答应建议关注或遵循当地官方通知，不代表已经执行任何动作；没有完整地点、时间、强度或官方预警时，不得给出具体撤离时间、范围、路线、登陆时间、风速或某条道路一定安全的结论。

因此：解释“准备应急包、关注当地官方通知、避免进入受损建筑”等通用建议的 chunk 可为 `3`；只说明某一灾害的分析要点或缺失字段限制的 chunk 可为 `2` 或 `1`；没有实时上下文却给出某地的具体撤离指令、半径、时间或现场调度的内容应为 `0`。

## 一致性要求

- 相同证据对不同 query 的等级由 query 意图决定；不要因为某 chunk 在另一条 query 中是 `3` 就复用该标签。
- 近似词不是充分条件。必须判断 chunk 是否真正提供当前问题所需的事实、规则或限制。
- `3` 和 `2` 都可以有多个，但 `3` 只给能直接支撑核心答案的 chunk；背景性、定义性或限制性材料不要拔高。
- 对不完整或异常的 `hazard_context`，优先标注说明缺失字段、摘要截断、来源差异或非官方性质的 chunk；不要补造实时事件。
- 所有 rationale 使用中文、简明且可追溯到候选原文。不要写“分数高所以相关”或“排名靠前所以相关”。
