# Prometheus Global Guardian 灾害分析 RAG 知识库

## 1. 用途和回答边界

本知识库服务于 `Prometheus Global Guardian RAG` 工作流。它提供稳定的灾害分析规则、数据字段含义、数据源解释和安全边界；请求中的 `hazard_context` 提供实时灾害快照。

回答必须区分三类信息：

1. **实时事实**：只来自请求中的 `hazard_context`，例如事件总数、类型数量和近期事件摘要。
2. **知识规则**：来自本知识库，例如灾害类型含义、严重程度解释和通用行动建议。
3. **分析判断**：根据实时事实和知识规则得出的风险判断，必须说明依据和限制。

本助手不是官方预警系统、应急调度系统或现场指挥系统。回答不能替代当地政府、专业机构、气象机构、地震机构或现场人员的判断。知识库中的建议是通用准备和复核建议，不代表已经执行的动作。

## 2. 工作流输入

工作流接收以下输入：

| 字段             | 类型   | 说明                                                              |
| ---------------- | ------ | ----------------------------------------------------------------- |
| `user_input`     | string | Guardian 用户的问题、分析目标或关注的灾害类型。                   |
| `hazard_context` | object | Guardian 当前灾害数据快照。可能为空或不完整。                     |
| `location`       | string | 地区、国家或 `global`。缺失时按全球范围理解，但必须说明范围假设。 |
| `language`       | string | `zh` 输出中文，`en` 输出英文。未提供时默认英文。                  |

实时上下文的字段结构：

- `total`：由当前请求提供的实时事件记录数。
- `byType`：由当前请求提供的类型到数量的映射。
- `recent`：由当前请求提供的事件摘要数组，每项可能包含 `title`、`type`、`severity`、`timestamp` 和 `magnitude`。

本知识库不提供任何示例事件数量、示例地点、示例时间或示例灾害组合。文档中的字段说明不是实时快照，模型不得把检索到的字段示例或规则内容当成当前事件事实。

字段含义：

- `total` 是当前请求快照中的记录数量，不等于现实世界的全部灾害数量。
- `byType` 是当前请求按灾害类型编码统计的记录数量。
- `recent` 通常只包含当前列表前 8 条摘要，不保证覆盖全部事件，也不保证已经按时间排序。
- `recent` 没有完整坐标、完整描述和原始链接，因此不能从中编造精确位置、伤亡人数或来源 URL。
- `hazard_context` 缺失、为空或格式异常时，必须在 `limitations` 中说明实时数据不可用或不完整。

## 3. 灾害类型规则

Guardian 的统一灾害类型编码如下：

| 编码               | 中文名称 | 分析重点                                             |
| ------------------ | -------- | ---------------------------------------------------- |
| `EARTHQUAKE`       | 地震     | 震级、时间、地点、余震、建筑和次生灾害风险。         |
| `FLOOD`            | 洪水     | 影响区域、降雨或水位信息、低洼区域、疏散和交通风险。 |
| `VOLCANO`          | 火山     | 喷发状态、火山灰、熔岩、气体、航空和周边疏散风险。   |
| `WILDFIRE`         | 野火     | 火势、风向、干旱、烟雾、蔓延方向和社区暴露风险。     |
| `TROPICAL_CYCLONE` | 热带气旋 | 路径、风力、降雨、风暴潮、沿海和内陆洪水风险。       |
| `STORM`            | 风暴     | 强风、雷电、暴雨、冰雹、龙卷风和基础设施风险。       |
| `DROUGHT`          | 干旱     | 持续时间、水资源、农业、生态和高温叠加风险。         |
| `TSUNAMI`          | 海啸     | 震源、沿海预警、到达时间、海岸线和撤离路线。         |
| `LANDSLIDE`        | 山体滑坡 | 降雨、坡度、道路阻断、建筑暴露和次生滑坡风险。       |
| `UNKNOWN`          | 未知类型 | 保留原始编码，不要自行猜测具体灾害类型。             |

DisasterAware 展示层还可能出现 `EXTREMETEMPERATURE`、`INCIDENT`、`MANMADE`、`TORNADO`、`CYCLONE` 和 `WINTERSTORM`。遇到这些编码时保留原始编码，并在 `limitations` 中说明它们不一定经过 Guardian 的多源统一映射。

## 4. 严重程度解释

Guardian 的实时数据适配器通常使用以下三个值：

- `ADVISORY`：提示级别，需要关注，但仅凭该值不能判定没有危险。
- `WATCH`：观察级别，条件可能发展，需要持续监测和准备行动。
- `WARNING`：警告级别，建议提高人工复核和响应优先级。

严重程度是数据源适配后的平台字段，不一定等同于当地法律规定的预警等级。缺少 `severity` 时必须写“严重程度未提供”，不能自行补充。

来源映射规则：

- USGS 地震：`magnitude >= 6.0` 通常映射为 `WARNING`；`5.0 <= magnitude < 6.0` 通常映射为 `WATCH`；更低或缺失震级通常映射为 `ADVISORY`。
- NASA EONET：当前 Guardian 适配结果默认使用 `ADVISORY`，不能据此推断实际危险程度。
- GDACS：`Red` 映射为 `WARNING`，`Orange` 映射为 `WATCH`，其他或缺失级别映射为 `ADVISORY`。

## 5. 数据源解释

### USGS

USGS 主要提供地震 GeoJSON 事件。Guardian 使用事件 ID、标题或地点、震级、事件时间和坐标。USGS 震级是地震事件的量级指标，不是伤亡人数、经济损失或官方应急等级。

### NASA EONET

NASA EONET 提供开放状态的环境事件。Guardian 根据事件分类映射为野火、火山、洪水、风暴、干旱或山体滑坡等类型。当前适配器将这些事件默认标记为 `ADVISORY`，分析时必须结合其他字段和来源，不得把该值解释为官方风险结论。

### GDACS

GDACS 提供全球灾害事件和预警信息。Guardian 根据标题、描述和严重程度文本识别类型，并根据 `Red`、`Orange` 等级映射严重程度。标题或描述无法识别类型时使用 `UNKNOWN`。

### DisasterAware

Guardian 通过 Express `/api` 代理访问 DisasterAware。DisasterAware 原始字段可能包括 `hazard_ID`、`hazard_Name`、`type_ID`、`severity_ID`、`latitude`、`longitude`、`start_Date`、`end_Date` 和 `description`。原始字段与统一 `Hazard` 字段不是同一套命名，回答时先确认数据是否已经标准化。

## 6. 按灾害类型的分析和建议

以下建议只在用户询问对应灾害，或实时上下文包含对应类型时使用。若没有地点、时间、强度或官方预警信息，建议必须标记为通用建议。

### 地震 `EARTHQUAKE`

分析要点：确认 `magnitude` 是否存在；查看 `severity`、时间和地点摘要；说明震级不能直接代表具体地点的损失；关注余震、建筑安全、滑坡、火灾和海啸等次生风险。

通用建议：关注当地官方地震和海啸通知；避免进入受损建筑；准备通讯、饮水、急救和照明物资；确认家庭或组织的集合点和疏散路线。没有完整位置和预警信息时，不要给出具体撤离时间或范围。

### 洪水 `FLOOD`

分析要点：确认事件数量和地区信息；查看是否同时存在风暴、强降雨或山体滑坡类型；识别低洼地区、河流沿线、道路和基础设施可能受到的影响；不要仅凭事件数量推断水位或受灾人口。

通用建议：遵循当地疏散通知；不要步行或驾车穿越未知深度积水；提前准备饮水、药品、照明和通讯设备；关注河流水位、降雨和道路封闭信息。没有水位、降雨和位置数据时，不要估算淹没深度。

### 野火 `WILDFIRE`

分析要点：确认事件位置、时间、风向和烟雾信息是否存在；关注火灾与干旱、高温、风暴的叠加；区分“监测到事件”和“火势正在向某地蔓延”。

通用建议：遵循地方疏散指令；准备随身药品、证件、饮水和通讯设备；关闭或过滤室内空气入口以减少烟雾暴露；不要根据模型回答判断某条道路一定安全。

### 热带气旋和风暴 `TROPICAL_CYCLONE` / `STORM`

分析要点：分别查看风、降雨、风暴潮和洪水风险；路径预测存在不确定性；沿海地区和内陆河流区域的风险可能不同；不要把事件数量当作风力或降雨量。

通用建议：关注气象和地方应急部门发布的路径及预警；准备停电、强风和暴雨所需物资；远离海岸、河道和受损电力设施；不提供未经数据支持的具体登陆时间或风速。

### 火山、海啸和山体滑坡 `VOLCANO` / `TSUNAMI` / `LANDSLIDE`

分析要点：火山要关注灰云、熔岩、气体和航空影响；海啸要确认是否有沿海官方预警，不能只由地震记录推断海啸；山体滑坡要关注降雨、坡地和道路阻断，但缺少这些字段时不得编造。

通用建议：优先遵循当地官方警报和指定撤离路线；远离海岸、火山危险区、陡坡和已封闭道路；准备应急包并保持通讯；没有官方预警或地点信息时，只给出准备建议，不发布自行撤离指令。

### 干旱 `DROUGHT`

分析要点：干旱风险通常需要持续时间、水资源、降雨和温度等时间序列，单个事件记录不足以完成趋势判断；应明确当前输入是否包含这些数据。

通用建议：关注当地水资源管理部门的用水通知；优先保障饮水、医疗和关键设施；将干旱与高温、野火风险一起复核；不要根据当前记录数量预测未来降雨或作物损失。

## 7. 风险等级输出规则

工作流要求 `risk_level` 只能是以下四个值：

- `LOW`：当前输入没有显示明显高风险信号，或只有低严重程度且信息有限的事件。
- `MEDIUM`：存在需要持续监测的事件，或上下文存在明显缺失，无法确认影响范围。
- `HIGH`：存在 `WARNING`、高震级、多个相关灾害叠加，或明确的人员、基础设施、沿海和疏散风险信号。
- `CRITICAL`：输入明确显示重大灾害、广泛影响或多个高风险信号同时出现，并且证据足以支持最高优先级人工复核。

风险等级是基于当前输入的分析标签，不是官方预警等级。仅有事件数量不能单独触发 `HIGH` 或 `CRITICAL`。证据不足时应选择较保守的等级，并在 `limitations` 中说明原因；不要输出 `UNKNOWN`，因为当前工作流系统提示词只接受以上四个值。

## 8. 工作流要求的 JSON 输出

大模型必须只返回有效 JSON，不使用 Markdown 代码块。字段必须与当前工作流提示词一致：

字段必须包括：`result`、`summary`、`risk_level`、`key_findings`、`recommendations`、`sources` 和 `limitations`。

输出字段约束：`result` 和 `summary` 是字符串；`risk_level` 只能是 `LOW`、`MEDIUM`、`HIGH` 或 `CRITICAL`；`key_findings`、`recommendations`、`sources` 和 `limitations` 必须是数组。不要从本知识库生成任何具体的当前事件数量、地点、时间或灾害组合。

字段规则：

- `result`：优先呈现结论、依据和下一步人工复核事项，保持简洁。
- `summary`：只概括当前输入能够支持的事实和判断。
- `risk_level`：只能使用 `LOW`、`MEDIUM`、`HIGH`、`CRITICAL`。
- `key_findings`：数组中的每一项都必须能追溯到实时上下文或本知识库规则。
- `recommendations`：使用“建议关注”“建议核实”“建议遵循当地通知”等表达，不写成已经执行的动作。
- `sources`：实时事实优先写 `Guardian hazard_context`；知识规则可写 `USGS`、`NASA EONET`、`GDACS` 或 `Guardian RAG knowledge base`。没有实际使用的来源不要列出。
- `limitations`：说明缺失字段、摘要截断、来源差异、去重限制和建议的非官方性质。

## 9. 典型问题到回答策略

### “请总结当前全球灾害态势，并按类型列出数量。”

读取 `hazard_context.total` 和 `hazard_context.byType`，按数量整理类型。不要把结果写成全球全部灾害，也不要添加上下文中没有的地区和时间。

### “当前洪水风险有多高？”

先确认 `byType.FLOOD`、近期洪水摘要、严重程度和位置是否存在；再结合洪水分析要点给出等级。只有数量、没有地点和严重程度时，应选择保守等级并说明信息不足。

### “请解释最近地震记录。”

使用 `recent` 中的标题、类型、震级、时间和严重程度。说明震级、平台严重程度和实际损失不是同一个概念，不推断伤亡或建筑损坏。

### “给出应急响应建议。”

根据灾害类型检索对应章节，输出通用准备、信息核实和官方通知优先级。不得伪造救援资源、撤离半径、登陆时间或现场指令。

## 10. 与当前代码的对应关系

本知识库与 Guardian 当前实现对应如下：

- `src/types/index.ts`：统一 `Hazard` 字段和核心灾害类型。
- `src/components/AIChatAssistant.tsx`：构造 `total`、`byType` 和最多 8 条 `recent` 摘要。
- `src/api/hazards.ts`：USGS、NASA EONET、GDACS 类型及严重程度映射。
- `src/workers/hazard-worker.ts`：坐标过滤和按事件 ID 去重。
- `hazards-source.js`：服务端多源灾害聚合。
- `server/ai/ai-provider.js`：工作流请求和 Guardian 系统提示词适配。

当前工作流的检索输入是用户问题和地区，实时灾害事实由 `hazard_context` 单独传给大模型。因此，本知识库负责稳定规则和解释，不存储实时事件，也不替代请求中的实时上下文。
